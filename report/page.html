Fairness notes

  • Routing, DB access, validation and the CPU workload live in one shared module that runs unchanged on all three runtimes. Each runtime only provides its own HTTP server: node:http, deno serve, Bun.serve.
  • All three use the same Postgres driver (postgres.js), installed once and copied into every image.
  • Multi-worker variants run one worker per CPU (4) and split the 50 database connections between them, so every app has the same total.
  • No request logging. Every container gets a 65535 open-file limit. The posts table is reset to the same 100 seeded rows before each run.
  • k6, Postgres and the server share the same 4 vCPUs, so absolute numbers are lower than on a dedicated setup. The comparison is still like for like.
